## 二、开源Agent框架分层分类总览（2026最新分层标准）
基于**底层能力、协作能力、开发门槛、生产成熟度**分为四大类，分类逻辑遵循从底层开发框架到可视化低代码平台，由重定制到零代码，覆盖全部用户人群：
1. 底层编程式Agent开发框架（面向Python/Java工程师，深度定制）
2. 角色化多智能体协作框架（业务流程、团队协同场景专用）
3. 低代码/无代码可视化Agent平台（无算法基础、业务人员快速搭建）
4. 端侧轻量化离线Agent框架（本地7B/13B小模型离线运行）

### 2.1 底层编程式Agent开发框架（核心开发主力）
该类框架为行业底层基础设施，生态完善、自由度最高，适合需要深度自定义调度逻辑、复杂DAG工作流、企业私有化二次开发的技术团队，是2026工业级Agent落地首选底座。

#### 2.1.1 LangGraph
- GitHub Stars：126K+（2026年8月数据）
- 核心定位：图状态机驱动的复杂Agent编排框架，LangChain官方下一代核心组件
- 2026核心升级：原生支持MCP协议、长任务持久化、人机介入循环、动态DAG重规划、故障断点续跑
- 核心优势
  1. 基于State状态管理，完美适配多步骤、带循环、带重试的复杂任务
  2. 细粒度流程控制，可拦截每一步工具调用、反思环节做自定义校验（适配Harness约束层）
  3. 完整可观测链路Trace，每一步执行日志结构化输出，便于线上监控
  4. 兼容全部LangChain生态：向量库、RAG、百余种工具插件
- 短板：学习曲线偏高，需要掌握图节点、状态传递逻辑，小型简单任务开发冗余
- 原生协议支持：MCP ✅；A2A 需扩展插件 ❌
- 适配人群：算法工程师、AI架构师、企业级复杂自动化项目
- 典型落地场景：科研数据分析Agent、全流程代码开发智能体、企业多步骤业务审批流水线

#### 2.1.2 LangChain
- GitHub Stars：124K+
- 核心定位：全栈通用Agent基础开发库，行业最早成熟生态
- 2026现状：基础模块稳定，复杂多智能体能力迁移至LangGraph，新项目官方优先推荐LangGraph
- 核心优势：插件生态最庞大，几乎兼容所有大模型、向量数据库、第三方工具，中文资料丰富
- 短板：原生无状态持久化，多轮复杂任务调度混乱，多Agent原生支持薄弱，大量API存在历史兼容技术债务
- 原生协议支持：MCP 第三方适配；A2A 无原生支持
- 适配人群：新手入门、简单单工具Agent快速Demo、小型知识库问答Agent
- 避坑提示：2026新建复杂生产项目不建议直接使用LangChain本体，优先LangGraph

#### 2.1.3 LlamaIndex
- GitHub Stars：46K+
- 核心定位：RAG+知识库增强型Agent专用框架，主打私有文档、企业知识库交互
- 2026核心升级：原生MCP文件资源调用、多模态文档解析Agent、长文本分段智能规划
- 核心优势：文档接入能力行业顶尖，支持PDF/Word/数据库/网页/音视频文本提取，内置多层检索优化，大幅降低幻觉
- 短板：通用工具调用、多智能体协作能力弱于LangGraph/AutoGen，纯流程自动化场景适配差
- 原生协议支持：MCP ✅；A2A ❌
- 适配人群：数据工程师、企业知识库开发者、文献科研助手搭建
- 典型场景：企业内部文档问答Agent、法律合同检索智能体、学术论文分析助手

#### 2.1.4 Semantic Kernel（微软）
- GitHub Stars：30K+
- 核心定位：跨语言企业级Agent开发框架，C#/Java/Python多语言原生支持
- 核心优势：微软云生态深度打通，权限管控、企业安全、插件沙箱机制完善，适合DotNet技术栈团队
- 短板：开源社区活跃度低于LangGraph，中文实战案例偏少
- 原生协议支持：MCP/A2A均提供官方SDK适配
- 适配人群：微软技术栈企业、政企私有化项目、Windows端桌面Agent

#### 2.1.5 PydanticAI（2026新兴热门框架）
- GitHub Stars：18K+
- 核心定位：类型安全、结构化输出优先的轻量化Python Agent框架
- 核心优势：依托Pydantic强类型校验，工具调用、规划输出强制JSON规范，大幅减少幻觉与格式错误，代码可维护性极强
- 短板：生态较新，第三方工具插件数量少，复杂多Agent编排能力尚在迭代
- 原生协议支持：MCP原生内置
- 适配人群：追求工程代码规范、线上稳定性的中小型开发团队

### 2.2 角色化多智能体协作框架（A2A场景专用）
专门针对**多角色分工、团队协同**场景设计，内置Agent角色定义、任务分发、角色间消息通信，原生适配2026 A2A智能体互通协议，适合复杂分工类业务。

#### 2.2.1 CrewAI
- GitHub Stars：46K+
- 核心定位：极简角色团队多Agent框架，低学习成本多智能体快速落地
- 2026升级：完整A2A协议原生支持、任务流Flow编排、角色记忆隔离、批量任务并发执行
- 核心优势：概念极度简洁，仅需定义Agent角色+任务，自动完成分工、协作、互相评审，1天可上手开发多智能体系统
- 短板：底层流程自定义空间有限，复杂循环动态规划场景能力弱于LangGraph
- 原生协议：MCP ✅、A2A ✅
- 适配场景：市场调研报告团队、内容创作流水线、财务数据分析小组、小型软件研发团队

#### 2.2.2 AutoGen（微软）
- GitHub Stars：53K+
- 核心定位：对话式多Agent交互框架，学术多智能体实验标杆
- 2026现状：基础版本进入维护模式，官方主推下一代MAF框架；现有项目仍可稳定运行，但无重大新功能迭代
- 核心优势：多Agent对话交互逻辑完善，内置代码沙箱执行，适合代码开发、数据科学自动化实验
- 短板：无原生状态持久化，大规模企业业务流程调度能力不足，A2A协议需二次封装
- 原生协议：MCP第三方适配、A2A 不原生支持
- 避坑提示：新项目多智能体协作优先CrewAI/MAF，存量项目可继续维护AutoGen

#### 2.2.3 MetaGPT
- GitHub Stars：67K+
- 核心定位：全流程软件研发多智能体，模拟完整互联网研发团队（产品、开发、测试、运维）
- 核心优势：垂直领域高度封装，输入需求文档自动输出完整代码项目、接口文档、测试用例
- 短板：场景高度垂直，脱离软件开发场景复用性极低，通用业务多智能体不推荐
- 原生协议：MCP基础适配

### 2.3 低代码/无代码可视化Agent平台（零算法门槛）
无需编写大量Python代码，可视化拖拽搭建Agent工作流，内置模型、工具、RAG组件，支持私有化部署，面向产品、运营、业务人员快速落地。

#### 2.3.1 Dify
- GitHub Stars：137K+（2026国内最热门开源低代码Agent平台）
- 核心定位：一站式可视化AI应用&Agent开发平台，内置RAG、工具调用、对话界面、API网关
- 2026核心升级：可视化MCP工具接入、多Agent协作画布、Harness安全约束配置面板、企业权限分级
- 核心优势：中文本地化完善，开箱即用，一键私有化部署，自带前端对话页面，支持导出API对接业务系统
- 短板：底层自定义调度逻辑受限，极致复杂DAG动态规划场景不如编程框架灵活
- 原生协议：MCP可视化配置 ✅；A2A 插件扩展支持
- 适配人群：业务人员、中小型企业快速搭建客服/办公Agent、无算法团队

#### 2.3.2 Flowise / Langflow
- Flowise Stars：48K；Langflow Stars：143K
- 核心定位：纯拖拽可视化工作流，兼容LangChain全部组件
- 优势：可视化调试每一步执行流程，零基础快速搭建单Agent工具链
- 短板：多智能体协作功能简陋，生产级权限、日志、监控能力薄弱，更适合Demo原型

### 2.4 端侧轻量化离线Agent框架（本地小模型离线运行）
适配7B/13B/34B本地开源大模型，无云端依赖、隐私安全，适合本地电脑、边缘设备离线智能体开发。
1. Llama Agent：基于Llama 3.2系列小模型轻量化工具调用微调框架，支持本地文件、本地脚本调用
2. Phi-Agent（微软）：Phi-3系列端侧模型专用Agent套件，移动端、本地PC低显存运行
3. LocalAGI：一体化离线Agent系统，内置向量库、本地搜索、代码执行沙箱，一键本地部署

## 四、分人群标准化选型指南（落地直接套用）
### 4.1 个人开发者/学生（算力有限、快速做Demo）
1. 知识库问答、文档分析：LlamaIndex
2. 简单多角色任务、调研报告：CrewAI
3. 本地离线小模型Agent：LocalAGI / Llama Agent
4. 可视化快速原型：Langflow

### 4.2 中小型企业无专职算法团队（业务人员主导）
首选Dify：开箱即用、自带前端页面、私有化部署、可视化配置，无需招聘AI工程师即可落地办公、客服、文档Agent。

### 4.3 互联网/软件研发团队（Python工程师，生产级复杂自动化）
核心底座LangGraph：复杂循环任务、工具调度管控、Harness安全约束、线上可观测链路完整，支撑长期迭代工业级Agent系统。

### 4.4 多角色团队协同业务（市场、财务、内容流水线）
首选CrewAI：原生A2A多智能体分工，开发速度快，角色记忆隔离，业务流程代码简洁易维护。

### 4.5 政企、DotNet技术栈、Windows私有化项目
Semantic Kernel：多语言兼容、微软生态安全管控、企业级权限审计完善。

## 五、2026框架避坑清单（淘汰/慎用项目）
1. 纯原生LangChain（无LangGraph）：复杂多步骤任务调度混乱，无状态持久化，长期迭代技术债务高，新项目禁止单独使用
2. 老旧AutoGen主版本：官方停止新功能开发，A2A/MCP无原生支持，多智能体通信需要大量二次开发
3. 无安全沙箱的轻量化Demo框架：如简易单文件Agent脚本，无操作白名单、无日志溯源，无法用于企业生产环境
4. 社区停止维护的小众框架：存在模型版本兼容漏洞、工具调用bug无人修复，线上稳定性无法保障

## 六、高频SEO适配FAQ
### Q1：MCP和A2A协议分别哪些框架原生支持？
MCP（Agent调用工具标准）：LangGraph、CrewAI、Dify、LlamaIndex、PydanticAI全部原生内置；AutoGen、Semantic Kernel仅第三方适配。
A2A（Agent之间互通标准）：仅CrewAI原生完整支持；LangGraph、Dify需安装官方扩展插件，其余框架无原生能力。

### Q2：7B本地小模型搭建Agent，选什么框架最合适？
端侧离线优先LocalAGI、Llama Agent；需要云端混合部署选LangGraph，搭配QLoRA轻量化微调工具调用权重，平衡离线能力与复杂规划。

### Q3：做企业知识库RAG+Agent一体化系统，最优框架是哪个？
垂直文档检索场景首选LlamaIndex；需要同时兼顾业务流程自动化、多工具调用则选LangGraph；无开发团队直接Dify可视化搭建。

### Q4：低代码平台Dify和编程框架LangGraph如何取舍？
短期快速上线、需求简单、无专职AI开发：Dify；长期持续迭代、复杂动态任务、强安全管控、大规模业务流水线：LangGraph。
