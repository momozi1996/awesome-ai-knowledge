# 01\-Agent 工程目录规范\.md

## 一、规范目的

本文档定义 **2026 生产级 AI Agent 工程标准化目录结构**，适用于：Agent 训练工程、微调工程、数据合成流水线、推理部署、私有化上线、开源项目托管。

解决行业普遍工程乱象：

- 脚本散落、文件混乱、无法批量迭代训练

- 数据、脚本、配置、权重混杂，无法区分版本

- 本地可跑、服务器/容器部署报错

- 多人协作冲突、无法沉淀工程资产

- 开源项目不规范、无法持续迭代维护

本规范**仅聚焦工程落地架构**，不重复前文理论知识，主打**模块化、解耦、可复用、可流水线自动化**。

## 二、核心设计思想（工程级）

整套目录遵循四大工程原则：

1. **数据与代码分离**：原始数据、处理后数据、合成数据、缓存数据分层隔离

2. **配置与逻辑分离**：所有超参、路径、模型配置写入 config，代码零硬编码

3. **训练与推理分离**：训练管线、评估管线、部署管线完全解耦

4. **资产与脚本分离**：权重、日志、评测结果、缓存统一归档，不污染源码

## 三、完整生产级目录结构（可直接落地）

## 四、关键目录工程职责详解

### 4\.1 configs 配置层（工程解耦核心）

所有**超参数、路径、模型尺寸、量化精度、学习率、batch、训练轮数、过滤规则**全部写入配置文件。

禁止代码硬编码，实现：

- 一键切换 7B/13B/34B 模型训练

- 一键切换 QLoRA/LoRA/全参数训练模式

- 批量迭代超参、快速消融实验

- 多人协作配置统一、可追溯

### 4\.2 core 核心源码层

存放 Agent 专属工程能力，区别于普通 LLM 项目：

- **tool\_parser**：解决 MCP 工具调用解析报错、格式错乱、参数不合法问题

- **planner**：工程化任务拆解、子任务依赖校验、重规划逻辑

- **agent\_pipeline**：统一封装训练、微调、推理入口，降低上手成本

### 4\.3 data\_pipeline 数据工程层

实现数据**来源可追溯、过程可复现、缓存可复用**：

- raw\_data 永远只读，禁止修改原始数据

- synth\_data 存放自动化合成批量样本

- process\_data 为最终入训练集标准数据

- cache 存放 tokenize 缓存、向量缓存，大幅提速迭代

### 4\.4 train\_pipeline 训练工程层

将 SFT、DPO、RL、分布式训练**完全模块化拆分**，解决：

- 单文件代码臃肿、难以维护

- 不同训练范式互相干扰

- 多卡训练逻辑混乱、断点续训失效

### 4\.5 outputs 资产输出层（重点规范）

所有训练产物**统一输出至 outputs**，不散落根目录：

- checkpoints：断点续训文件，防止训练中断重来

- lora\_weights：轻量化微调权重，用于迭代、切换场景

- merged\_weights：合并权重，用于生产部署

- logs：全量日志，用于监控、复盘、异常排查

## 五、工程强制规范（团队协作必守）

### 5\.1 文件命名规范

- 所有文件夹、脚本统一 **下划线命名**

- 训练脚本固定前缀：train\_xxx\.py

- 数据脚本固定前缀：data\_xxx\.py

- 评测脚本固定前缀：eval\_xxx\.py

### 5\.2 代码分层规范

- 入口脚本极简，只负责调用管线

- 核心逻辑全部封装 core/

- 所有可变参数读取 configs/

- 所有输出写入 outputs/

### 5\.3 Git 提交规范

\.gitignore 必须永久忽略：

- 所有权重、checkpoint、缓存文件

- 日志、临时文件、环境变量文件

- 本地设备专属配置

## 六、目录架构优势（生产落地价值）

1. **可迭代**：数据、训练、权重、版本完全隔离，支持长期持续迭代

2. **可复现**：配置统一、流程标准化，任意设备均可复现训练结果

3. **可扩展**：新增训练范式、新数据类型、新部署方式无需重构目录

4. **可开源**：完全符合 GitHub/Gitee/魔搭开源项目规范

5. **可团队协作**：模块解耦、职责清晰、多人开发不冲突
