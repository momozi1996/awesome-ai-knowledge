# 03\-数据工程流水线\.md

## 一、文档定位

本文属于 **Agent 工程与训练实战体系** 第三章，完全聚焦**工程落地流水线**，不重复前期理论层的数据范式。重点解决：**数据杂乱、格式不统一、脏数据炸训练、token冗余、样本不均衡、流水线不可复现、无法批量迭代**等真实工程问题。

理论文档告诉你「Agent需要什么数据」，本文告诉你：**如何工程化生产、清洗、过滤、缓存、分批、校验、固化一条可长期迭代的Agent数据生产线**。

数据是Agent稳定性上限，训练翻车、微调退化、工具调用错乱、幻觉反弹，90%源于**数据工程不规范**，而非模型算法问题。

## 二、Agent数据工程核心痛点（工程侧）

普通LLM数据流水线无法适配Agent，存在大量工程盲区：

- 通用文本数据混入训练集，导致Agent**行为范式崩坏**

- 工具调用样本格式不严格，训练后解析报错、参数错乱

- 正负样本比例失衡，模型要么不敢调用、要么乱调用

- 无数据缓存机制，每次训练重复tokenize，极度耗时

- 无分层采样，简单样本过多、复杂轨迹样本被淹没

- 无数据校验机制，脏数据、空样本、超长样本直接入训

- 数据版本混乱，迭代无法复现、无法溯源

## 三、Agent工业级数据流水线总架构

整套流水线为**6阶标准化工程流程**，全程脚本自动化、可批量、可复现、可版本固化：

**原始数据源 → 自动化合成 → 结构化清洗 → 规则过滤 → 分层采样 → 缓存固化 → 训练投喂**

### 3\.1 流水线工程设计原则

- **只读原始数据**：raw数据永不修改，所有生成、处理产物独立输出

- **阶段产物隔离**：合成、清洗、过滤、采样分文件夹存放，可单独回溯

- **强格式校验**：Agent结构化字段强制校验，非法样本直接拦截

- **全量缓存机制**：tokenize结果、mask、position缓存落地，提速10倍\+

- **版本可固化**：每一轮数据集生成对应版本号、参数、日志

## 四、各阶段工程落地细则

### 4\.1 原始数据层（raw\_data）

存放所有**未经处理的原始素材**：开源Agent数据集、人工标注样本、LLM自动合成原始轨迹、业务真实对话日志。

工程强制约束：

- 禁止直接在raw目录修改数据

- 所有原始文件命名带来源标签与时间戳

- 保留原始字段、原始格式，用于问题回溯

### 4\.2 自动化合成层（synth\_data）

承接自动数据合成脚本，批量产出：

- 工具调用单步样本

- 多步骤规划轨迹样本

- 反思纠错样本

- 异常、边界、负样本

- 多智能体协作交互样本

工程输出格式统一为 **jsonl**，每行一条独立样本，适配批量处理与流式加载。

### 4\.3 结构化清洗工程（核心）

Agent数据**不能只做文本清洗**，必须做**结构化字段清洗**。

统一清洗规则（工程脚本固化）：

1. **字段完整性校验**：instruction、input、output、tool\_call、thought、history 关键字段缺失直接剔除

2. **工具格式强校验**：JSON格式合法性、参数key合法性、无多余嵌套、无语法残缺

3. **空样本过滤**：空思维、空调用、空结果样本直接丢弃

4. **文本标准化**：去除多余换行、空格、特殊不可见字符、markdown乱码

5. **去重策略**：基于instruction\+tool\_call组合去重，避免高度重复样本过拟合

### 4\.4 分层规则过滤（Agent专属）

普通LLM只过滤脏文本，Agent需要**按能力维度分层过滤**，保证训练集质量梯度健康。

#### 4\.4\.1 基础过滤

- 单样本token长度超限截断/剔除

- 超长思维链、无效冗余思考过滤

- 虚假工具调用、编造参数、空参数样本剔除

#### 4\.4\.2 高阶业务过滤

- 步骤逻辑冲突、子任务依赖错乱样本剔除

- 过度简单样本（无思考、无规划、直接输出）降权采样

- 负样本强度均衡：弱错误、中度错误、重度错误比例均衡

### 4\.5 分层采样与均衡配比

训练效果差、泛化弱、上线翻车，大多是**样本比例畸形**导致。

2026工业级Agent训练集配比标准（可直接复用）：

- **基础工具调用样本 40%**：保证基础调用稳定性

- **多步骤规划轨迹样本 35%**：保证长链路任务能力

- **反思纠错/负样本 20%**：降幻觉、提容错

- **多智能体协作样本 5%**：保证团队交互能力不退化

工程实现：脚本自动分层抽样，强制比例约束，避免数据集偏向单一能力。

### 4\.6 数据缓存工程（提速核心）

训练最大工程浪费：**每轮训练重复tokenize、重复mask生成**。

流水线强制开启缓存机制：

- 对清洗后稳定数据集，一次性生成：input\_ids、attention\_mask、labels、position\_ids 缓存文件

- 缓存按模型尺寸、max\_seq\_len、tokenizer版本打标签，防止版本混用

- 无变更数据集直接加载缓存，训练启动速度提升 8–15 倍

## 五、数据集标准化输出格式（训练管线唯一入口）

所有进入训练、微调、DPO对齐的数据，最终统一为**Agent标准对话结构**，杜绝格式混乱导致训练loss异常。

```json
{
  "instruction": "用户原始需求",
  "input": "上下文/工具返回内容",
  "output": "模型最终结构化输出",
  "thought": "内部推理规划过程",
  "tool_call": {},
  "history": [],
  "difficulty": "easy/medium/hard",
  "sample_type": "sft/dpo/negative/collaborate"
}
```

## 六、数据集自动切分工程

禁止人工随机切分，工程脚本固定随机种子，保证可复现。

### 6\.1 切分比例（Agent最优）

- 训练集 train：90%

- 验证集 val：10%

- 测试集 test：独立离线业务用例（不参与随机切分）

### 6\.2 切分强制规则

- 固定 seed=42，所有版本迭代切分一致

- 按难度、样本类型分层切分，保证分布一致

- val集绝不参与训练数据混入，杜绝虚高指标

## 七、数据版本管理工程（团队必备）

数据比模型更需要版本管理，解决迭代混乱、无法溯源、效果波动问题。

每一轮数据集产出必须附带：

- **数据版本号**：data\_v2026\_xx

- **样本总量、各类型数量统计**

- **过滤规则参数快照**

- **采样比例配置快照**

- **缓存参数、序列长度**

- **迭代变更日志**：新增、优化、剔除规则说明

模型训练版本与数据版本一一绑定，实现**全链路可溯源复现**。

## 八、流水线自动化脚本架构（极简总览）

整套流水线完全脚本化，一键执行全流程：

- `data_synth.py`：批量合成Agent轨迹样本

- `data_clean.py`：结构化清洗、去重、脏数据剔除

- `data_filter.py`：分层规则过滤、难度筛选

- `data_sample.py`：均衡分层采样

- `data_cache.py`：tokenize缓存生成与加载

- `data_split.py`：训练/验证集自动切分

- `data_stat.py`：数据集统计、质检报告生成

## 九、工程避坑清单（高频翻车点）

- **禁止混入通用对话数据**：一旦混入，Agent工具范式退化、执行崩坏

- **禁止样本比例失衡**：简单样本过多导致过拟合、复杂任务能力缺失

- **禁止跳过缓存**：无缓存训练迭代效率极低，无法多轮消融实验

- **禁止动态随机切分**：随机种子不固定，每次训练数据集不同，指标不可对比

- **禁止忽略负样本**：无负样本数据集，模型容错极低、上线幻觉爆炸

- **禁止格式不统一**：训练、微调、DPO使用不同格式，直接导致loss震荡、不收敛

## 十、本章小结

本章完整落地 **Agent工业级数据工程流水线**，从原始数据、合成、清洗、过滤、采样、缓存、切分、版本管理形成闭环工程体系。彻底解决传统LLM数据处理无法适配Agent结构化、工具化、轨迹化训练的工程短板，为后续单/多卡训练、微调对齐、稳定迭代提供**高质量、可复现、可量产的数据底座**。

数据工程稳定后，模型训练的效果波动、随机翻车、能力退化问题可减少 80% 以上。
