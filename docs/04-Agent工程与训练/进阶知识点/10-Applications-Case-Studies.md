
# 10 应用与案例 (Applications & Case Studies)

> 实际应用、成功案例、最佳实践、行业解决方案

**内容重点**: 落地应用，实战经验

---

## 1. 本章定位
本文是完整AI Agent项目实战手册，覆盖从需求立项、方案选型、数据集建设、训练开发、评测、灰度上线、持续迭代的完整全生命周期。
可直接作为 awesome‑ai‑knowledge 仓库的实践总纲，适合团队内部做项目checklist，也适合个人开发者从零搭建Agent项目对照使用。

> [!NOTE]
> 本手册面向**基于LLM微调的私有Agent**；同时兼容部分无微调、仅Prompt编排的Agent项目，会标注两者差异点。

## 2. Agent项目生命周期总览

```mermaid
flowchart LR
A[需求与边界定义] --> B[方案选型与技术决策]
B --> C[工具定义 & Schema设计]
C --> D[数据集建设：人工种子 + 蒸馏 + 清洗校验]
D --> E[训练脚手架Harness开发调试]
E --> F[离线评测集搭建 & 基线确立]
F --> G[SFT训练、验证、门禁评审]
G --> H[DPO偏好训练、验证、门禁评审]
H --> I[推理运行时基础设施开发<br/>MCP/状态机/埋点]
I --> J[全链路闭环测试、版本门禁]
J --> K[灰度发布、流量切分]
K --> L[线上指标观测、badcase回流]
L --> M[数据集迭代，循环迭代C‑K]
```

> 
> 无微调Prompt‑Only Agent：跳过D/E/G/H，直接从C进入I。

## 3. 阶段一：需求立项与边界定义

> 
> 很多Agent项目失败源于需求模糊，什么都想做，能力边界不收敛。

### 输出交付物

1. 业务目标文档：Agent要解决什么问题，核心价值；
2. 能力边界清单：明确哪些做、**哪些不做**；
3. 用户输入范围：预期用户query分布；
4. 成功指标：业务层面可衡量的目标（任务完成率、工具调用成功率）。

### 关键问题自检

- Agent是解决什么场景？是工具调用Agent、多步骤任务Agent，还是对话助手？
- 必须用到哪些工具？哪些能力不在范围内？
- 输入是否会出现大量分布外query？
- 预期上线后的性能约束：延迟、并发、成本。

> 
> 风险提示：不要立项“通用超级Agent”，垂直场景收敛边界更容易拿到可用结果。

## 4. 阶段二：方案选型与技术决策

### 两大路线对比

| 方案路线 | 描述 | 优势 | 劣势 | 适用场景 |
| --- | --- | --- | --- | --- |
| 路线A：仅Prompt编排，不微调 | 基座大模型 + System Prompt + LangGraph编排 | 交付快，无需训练算力；迭代灵活 | 高度依赖基座能力；工具格式稳定性差；高并发成本高 | 原型验证、业务快速试错、业务频繁变更 |
| 路线B：SFT+DPO微调Agent | SFT轨迹微调 + DPO偏好对齐；运行时做轻量编排 | 输出格式稳定，行为可控；推理成本更低；行为固化 | 需要算力；数据集建设成本；版本迭代周期长 | 业务场景稳定，工具集合固定，需要大规模上线 |

> 
> 实践建议：优先Prompt‑Only做原型验证，确认业务可跑通之后，再启动微调路线。

### 基座模型选型决策

1. 业务复杂度低：7B‑13B开源基座，QLoRA微调；
2. 多步骤强规划业务：优先34B及以上基座；
3. 蒸馏方案：强教师模型生成轨迹，训练小尺寸学生模型。

> 
> 重要认知：基座能力决定Agent能力上限，微调只能对齐行为范式，不能凭空创造基座不存在的推理能力。

## 5. 阶段三：工具定义、Schema设计

### 交付物

1. 完整工具集MCP Schema定义（统一一份，数据集、训练、推理三方共用）；
2. 每个工具的入参、出参、错误返回样例。

### Schema设计最佳实践

1. 字段尽量精简，字段越多，模型输出出错概率越高；
2. 明确每个字段类型、是否必填；
3. 提前定义错误返回文本格式，后续喂入训练数据集；
4. Schema变更视为重大版本变更，需要同步更新数据集、评测集。

> 
> 高危坑：训练数据集一套schema，线上MCP另一套schema，上线后大规模调用报错。

## 6. 阶段四：数据集建设（项目核心重资产）

### 交付物

1. 人工种子轨迹集；
2. 蒸馏生成原始数据集；
3. 经过清洗校验的SFT训练集；
4. DPO偏好数据集；
5. 冻结离线评测集（严格隔离，不混入训练）。

### 标准工作流

1. 人工编写种子样本，覆盖正常、边界、失败重试case；
2. 使用强教师模型做轨迹蒸馏，Few‑shot注入人工种子样本；
3. 自动化流水线校验：JSON、schema、去重、过滤坏样本；
4. 人工抽样质检；
5. 混合人工种子样本与过滤后的蒸馏样本，构成SFT数据集；
6. DPO数据集以人工偏好对为主，蒸馏偏好对仅作为补充。

> 
> 数据集版本必须完整归档，每一次训练绑定数据集ID。

## 7. 阶段五：训练脚手架Harness开发

### 交付物

1. 可复现训练工程代码；yaml配置文件；
2. 数据集预处理公共函数（训练、校验、推理三方复用）；
3. docker/conda环境锁定依赖版本；
4. 单元测试：预处理逻辑单元测试。

### 关键约束

1. Agent SFT训练关闭packing，防止破坏对话边界；
2. DPO训练固定ZeRO‑2，避免ZeRO‑3；
3. LoRA参数SFT/DPO保持一致；
4. 全局固定随机种子，保证可复现；
5. 训练结束自动归档实验元数据。

> 
> 脚手架的bug经常伪装成模型效果问题，预处理逻辑必须单独单元测试。

## 8. 阶段六：离线评测体系搭建 & 确立基线

### 交付物

1. 冻结私有业务评测集；
2. 评测脚本：自动跑完整Agent闭环；
3. 版本门禁指标基线。

### 门禁指标示例

- JSON格式通过率 ≥ 88%
- 工具选择正确率 ≥ 85%
- 过度调用率、拒绝调用率低于阈值
- 多步骤任务完成率达到业务基线

> 
> 离线评测不通过，不允许进入下一阶段。

## 9. 阶段七：SFT训练 → DPO训练，迭代验证

1. 执行SFT训练；跑完全套离线评测；
2. SFT指标达标，产出SFT LoRA；
3. 在SFT权重基础上执行DPO偏好训练；
4. DPO完成后再次完整跑全套评测；
5. 对比基线，禁止指标断崖退化；退化则回退，排查数据集、超参。

> 
> 不要跳过SFT直接跑DPO；DPO是对齐偏好，不是学习新范式。

## 10. 阶段八：推理运行时基础设施开发

### 交付物

1. Agent Runtime；MCP工具网关；状态机；记忆模块；
2. 完整埋点日志体系；
3. 最大迭代轮次强制终止，防死循环；
4. 公共prompt模板库，与训练侧完全复用。

### 必须完成校验项

1. 训练‑推理一致性全量核对清单执行一遍；
2. 模拟完整会话闭环测试；
3. 故障模拟：工具报错、参数非法，验证Agent行为。

> 
> 微调完成不等于项目交付，运行时基础设施占Agent项目一半工作量。

## 11. 阶段九：全链路测试、版本门禁评审

1. 离线评测集批量自动化测试；
2. LLM‑as‑Judge辅助打分；
3. 人工抽样评测；
4. 回归case全部跑通；
5. 对比上一版本基线，确认无断崖退化。

门禁不达标，打回迭代，不允许上线。

## 12. 阶段十：灰度发布 & 线上运行

1. 小流量灰度，比如10%流量；
2. 持续观测大盘指标：JSON失败率、任务完成率、工具调用统计；
3. 准备好权重快速回退预案；
4. 灰度稳定后逐步放大流量。

> 
> 线上出现全局指标恶化：优先回退止损，再定位根因。

## 13. 阶段十一：线上迭代闭环

1. 通过埋点采集线上会话；
2. bad case人工打标签归类根因；
3. 分类处理：
   - 工程bug：修复代码，沉淀单元测试；
   - 能力缺失：清洗为训练样本，加入数据集；同时加入离线评测集作为回归case；
   - 分布外OOD case：优先上层编排兜底，不盲目灌入训练集；
4. 新一轮训练迭代，循环整个流程。

> 
> Agent项目不是一次性交付，是持续迭代闭环。

## 14. 项目风险清单与风险对策

| 风险点 | 风险描述 | 应对策略 |
| --- | --- | --- |
| 需求膨胀，边界不断扩大 | 什么功能都要做，项目不可收敛 | 立项阶段明确能力边界，非核心需求排后续版本 |
| 过度迷信微调，忽略工程 | 把全部希望寄托于模型训练，忽视运行时、schema、模板对齐 | Prompt‑Only先跑原型；重视训练‑推理一致性校验 |
| 数据集质量差，大量脏样本 | 蒸馏不做过滤，直接喂原始输出训练 | 强制自动化校验+抽样人工质检；数据集版本管理 |
| 训练‑推理不一致 | 模板、schema、tokenizer线上线下不一样 | 公共组件三方复用；上线前执行一致性核对清单 |
| 评测缺失，只看loss | loss下降就认为效果好，上线大量问题 | 必须跑完整Agent闭环评测，建立版本门禁 |
| 版本迭代能力遗忘退化 | 新增样本之后旧能力变差 | 保留回归测试case；版本对比基线；指标断崖直接回退 |
| 上线无回退预案 | 出问题无法快速止损 | 权重版本快速切换，准备降级策略 |

## 15. 最小交付物清单（项目结束必须产出）

1. 业务需求与能力边界文档
2. MCP工具Schema全集
3. 数据集版本归档（训练集、评测集）
4. 训练代码、配置、依赖锁定文件
5. 实验元数据记录（git hash、超参、种子）
6. 离线评测集与评测脚本
7. Agent运行时代码、埋点规范
8. 故障排查SOP、回退预案
9. bad case归档库与回归用例

## 16. 本章小结

1. Agent项目完整生命周期：需求定义 → 选型 → schema设计 → 数据集 → 训练脚手架 → 评测 → 运行时开发 → 灰度上线 → 持续迭代。
2. 优先使用Prompt‑Only做原型验证，业务确认可行再上微调。
3. 数据集、评测、运行时基础设施，工作量往往大于模型训练本身。
4. 严格版本门禁，离线不达标不上线；线上故障优先止损回退，再定位根因。
5. Agent是持续迭代系统，线上bad case回流形成闭环。
